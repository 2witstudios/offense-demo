# ADR 0007: PostgreSQL as the durable source of truth

Status: accepted. Amended by [ADR 0018](0018-cuid2-identifiers.md) and
[ADR 0023](0023-greenfield-baseline.md): identifiers are cuid2 `text`, not
UUIDs; the conventions below state the current rule. Amended by
[ADR 0038](0038-drizzle-1-baseline.md): Drizzle is 1.0.0-rc.4.

Durable records — users, sessions, credentials, and every product record a
project adds — are authoritative only in PostgreSQL. Application
in-memory state and Redis are rebuildable at all times. Drizzle over
Bun's native SQL gives typed queries, transactions, and reviewed migrations
without a second runtime driver (ADR 0012).

Conventions: cuid2 identifiers (`text` columns) generated by the application
before the write;
`timestamptz` with UTC ISO strings; integer milliseconds for durations;
immutable `created_at`; explicit `updated_at` on mutation; optimistic
`version` starting at 1 where concurrent mutation exists. Migrations are
generated (`bun db:generate`), reviewed as SQL, committed with metadata,
applied once per release, never rewritten after being applied; destructive
changes follow expand/contract for rolling deployments.

Tradeoffs: JSON snapshots of domain state (rather than fully normalized
tables) buy portability across domain evolution at the cost of SQL-level
querying of internals; promote the fields real queries filter on to
searchable columns. Normalize specific snapshots only when real queries
demand it.
