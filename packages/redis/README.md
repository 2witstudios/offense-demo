# @offense-demo/redis

Owner: Platform/infrastructure (see CODEOWNERS scaffold).

Ephemeral storage with mandatory TTL, versioned namespaces, health and cleanup. Public API: createRedis, redisKey, RedisConfig, `@offense-demo/redis/namespaces` (namespace administration and the test-run sweep) and `@offense-demo/redis/testing` (`testNamespace`, `withBoundedExpiry`, `createBoundedTestClient`: the expiry ceiling every integration key is held to, ISSUE-237), and the presence operations (upsertPresenceLease, refreshPresenceLease, deletePresenceLease, readUserConnections, readOnlinePresence, sweepOnlinePresence). Depends on Bun and `@offense-demo/protocol` (presence and id validation only). Never store the only copy of durable records: PostgreSQL is the source of truth (ADR 0007). Cluster/Sentinel and pub/sub are outside the supported adapter contract.

Presence Lua scripts assume a single-node Redis (ADR 0008): a connection-hash key name is built inside `readUserConnections`'s script from a validated prefix plus the zset's own connId members, rather than declared through `KEYS`, which is only required for Redis Cluster's client-side slot routing. Every script is `SCRIPT LOAD`ed once and run by `EVALSHA`, reloading and retrying once on `NOSCRIPT`. Every presence read is bounded and read-only: `readOnlinePresence` takes a mandatory `limit` (`online` is a single global key) and `readUserConnections` returns at most 32 live connections, latest expiry first; lapsed members are filtered by score, never deleted by a read. The upsert, refresh and delete scripts trim a user's lapsed connections on the write path, and `sweepOnlinePresence(limit)` trims the online set; the web server's retention sweep runs it hourly. Every `limit` is capped at 1000, far below Lua's `unpack` ceiling.

Run `bun run typecheck` and `bun test src` from this package. Integration-enabled packages expose `bun run test:integration`; tests require explicit test infrastructure variables. All imports use the public package export.
