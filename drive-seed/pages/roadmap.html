Status model

  • To Do = groomed and eligible · Ready = committed: selected for work now · In Progress → Blocked / In Review → Merged → Done.
  • Status lives in the status field, never the title. Commitment is a status; nothing moves folders.
  • Agents keep their own tasks current up to In Review. The merge workflow moves a merged task to Merged; Done is granted only from an independent review record, never by the agent that did the work.
  • A parent can't complete while a child is open — status is the only progress marker.
  • Blocked longer than 24h → post to {{page:incidents}} with the task ID and owner.
  • Leaf bodies are acceptance criteria — "Given X, should Y" — each mapping to one provable assertion (test, command exit, or page state). Em-dash — between label and description; middle dot · for numbered steps.
  • Execution leaves gate on TDD: RED — failing test, then GREEN — implementation.
  • A human-only sign-off leaf gates deploys and anything touching production data. Agents never self-approve these.

Ceremonies — agent-run

  • Daily standup — every active agent posts Yesterday / Today / Blockers to {{page:standup}}; the Scrum Master posts the digest and flags blockers.
  • Commitment — the Scrum Master or orchestrator grooms {{page:backlog}} candidates into epic leaves and sets the leaves selected for work now to Ready, posting the committed task IDs to {{page:epicUpdates}}. There is no timebox; only Ready leaves are claimed, and the epic plan in Plans/<Epic> holds dependencies and order.
  • Review — an independent Reviewer proves each candidate's acceptance criteria with command output and publishes a review record in Reviews/<Epic>; Done is granted only from that record.
  • Retro — at phase or epic close; findings go in the closing review record and land as edits to this page or to {{page:agentMemory}}.

Channel routing

  • {{page:standup}} — daily agent check-ins and the Scrum Master digest.
  • {{page:sprintRoom}} — PR merge notices (posted automatically from CI) and cross-epic discussion.
  • {{page:epicUpdates}} — epic and leaf status transitions, completions, decisions made on the owner's behalf.
  • {{page:incidents}} — blocked work, CI and deploy failures, environment issues. Always with task ID, owner, and next action. CI posts its own failures automatically via webhook — don't duplicate.

Team

  • {{page:scrumMaster}} — coordination: grooming, commitment, standup digest, unblocking, ceremony posts. Never edits app code.
  • {{page:builder}} — implementation: RED→GREEN leaves, integration coverage, docs and ADRs updated in the same change. Contract: {{page:builderContract}}.
  • {{page:reviewer}} — quality gate: proves acceptance criteria, enforces AGENTS.md standards, blocks Done until proven. Contract: {{page:reviewerContract}}.
  • {{page:documentationAgent}} — maintains {{page:documentation}} (Canvas pages, Page Registry, Documentation Runs) from merge events per docs/architecture/documentation-pipeline.md; works the Review Queue.

Durable environment facts and work logs live in {{page:agentMemory}} — ceremonies and channels never duplicate them. The orchestrator owns Agent Memory writes. The rules for plans, prompts, handoffs and reviews are {{page:conventions}}.
