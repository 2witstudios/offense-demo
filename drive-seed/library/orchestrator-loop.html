Orchestrator stage loop

Universal prompt. Reused across epics. It names no task, plan or PR.

  1. Ground. Read the epic, its plan in Plans/<Epic>, the phase and leaf criteria, and the last review record. Reconcile the board with git before starting anything: bun board:stale lists tasks whose status disagrees with what merged. Then read the drive-root Issues list: any issue touching the files, package or phase about to be built goes into the stage prompt as a known debt the builder fixes while in that code.
  2. Settle decisions before fan-out. A new epic runs through the /task skill: plan draft, independent plan review (bun plan:review), owner approval, tasking, validation. Take ADR and migration numbers from bun adr:next. Declare each leaf's prerequisites on a Prerequisite: line in its Related pages.
  3. Commit. Work only on committed leaves: set them Ready on the board before anyone claims them, and post the committed task IDs and transitions to Epic Updates; CI posts merges to Sprint Room.
  4. Prompt. Write the task prompt as a page in Prompts/<Epic>. It carries only what is specific: scope, candidate, criteria page mentions, what to read first, the file scope (allowed and forbidden paths), known hazards and known debts. It @-mentions the universal contract it uses (Builder or Reviewer). Universal prompts never link back.
  5. Link. Add the prompt to the "Related pages" block of the phase and each leaf it covers (bun board:relate).
  6. Spawn. Start each agent with the repository's spawn tooling, giving it only pagespace pages read <promptPageId> — that page is your task; a reviewer joins the builder's existing worktree. Refuse a builder whose prerequisites are unmerged or whose leaf uses a superseded term, unless the owner overrides. The spawner installs dependencies, brings the slot up, registers you as the parent and confirms the prompt was submitted. Never delegate code to worktree-isolated subagents; forks are for read-only research.
  7. Track. Leaves move To Do → Ready → In Progress → In Review → Merged → Done. Agents keep their own tasks current up to In Review; the merge workflow moves merged tasks to Merged. Done is granted only from an independent review record, never by the agent that did the work.
  8. Branches. Every agent works on its own worktree's pu/<name> branch, one open vertical per agent, and never commits in the main checkout, which stays on main. Stacked PRs are merge-commit clean: fix the lowest branch first, then rebase the ones above it.
  9. Review and merge. Every PR gets an independent review record; its Candidate line mints the review-record check. The owner merges any PR whenever they choose, and the record may follow the merge. An autonomous agent never merges: it requests the merge with gh pr merge --auto --merge only after gh api repos/{{repo}}/rules/branches/main --jq '[.[] | select(.type == "required_status_checks") | .parameters.required_status_checks[].context] | any(. == "review-record")' prints true, and GitHub completes it only once every required check, review-record included, passes; otherwise the PR is reported "ready for owner merge". CHANGES REQUESTED goes back to the builder; at a third review pass on one leaf, stop and bring the open disagreement to the owner instead of starting another pass.
  10. Loops. PR loops use {{page:convergeLoop}}. A loop agent that cannot truthfully finish escalates instead of spinning; you close or resume it.
  11. Owner decisions. Criterion changes, scope cuts and human prerequisites belong to the owner. A decision you make on the owner's behalf is recorded with bun decision:record on the Pending decisions list, which notifies the owner and stays open until confirmed or overruled.
  12. Close. On acceptance: leaves Done, the epic's delivery log in Plans/<Epic> updated, related-pages blocks complete, durable lessons written to Agent Memory. A phase or epic cannot close while any issue it produced is untriaged: each is promoted to a leaf, scheduled into a stage prompt, or deferred by the owner with a recorded reason.
