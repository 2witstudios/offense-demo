Converge loop

Universal prompt. Reused for every PR loop. It names no task, plan or PR: the loop is started with the PR number, and this page is the whole loop prompt. It replaces pasting a loop prompt into a session.

Start it in the builder's worktree, once the PR is open:

/ralph-loop Run: pagespace pages read {{pageId:convergeLoop}} and converge PR #<n> by that page. --completion-promise CONVERGED --max-iterations 40

Each iteration

  1. Scan. Read the PR's review threads, bot reviews and comments, and the required checks. Pick up bot review comments yourself: a comment from CodeRabbit, Codex or another bot is a finding to triage (/triage), never something to wait for a human to relay.
  2. Fix. For each open finding that is in scope: fix it with a test (TDD), push, reply on the thread with the fixing commit, and resolve the thread you fixed. A thread that is fixed and replied to counts as done, whether or not the bot resolves it. A finding that is out of scope is filed (follow-up leaf or ISSUE-n) and replied to with the page id; that also counts as done.
  3. Bot reviews. A bot review that is still pending, rate-limited or skipped is not a clean review. Wait for it instead of declaring the PR ready. If it is rate-limited or skipped and will not run again on its own, escalate blocked.
  4. CI. Wait on CI without polling: run gh pr checks <n> --watch --fail-fast once in the background, and end the turn. Never loop gh pr checks.
  5. Stalled. Keep the last scan's summary (open threads, failing checks, pending bots) in your turn text. If two consecutive scans are identical and you changed nothing in between, escalate stalled.
  6. Third review pass. If an independent review of this PR's leaf would be its third pass, do not start or request another; escalate needs-owner with the open disagreement.

Escalate instead of spinning

When you cannot truthfully finish, pause the loop and tell your parent (or the owner) why, with one of these reasons. Never delete, move or edit the loop state, never end the loop yourself. Where the repository provides it, use bun loop:escalate <reason> "<what only the parent or owner can resolve>", which keeps your iteration and prompt, notifies your parent and records the escalation on the PR.

  • needs-owner: a decision, secret, criterion change or anything only the owner or a bot operator can resolve.
  • blocked: a rate-limited or skipped bot review, an outage, or a prerequisite that is not merged.
  • stalled: two identical scans.
  • out-of-scope: the remaining work belongs to another leaf or story.

Then stop; the parent closes or resumes the loop.

Done

The PR has converged when every thread is done as defined above, every bot review has run on the head SHA, every required check except review-record is green, and the handoff is current. Then check that the live main ruleset requires review-record with gh api repos/{{repo}}/rules/branches/main --jq '[.[] | select(.type == "required_status_checks") | .parameters.required_status_checks[].context] | any(. == "review-record")'. Only when it prints true, request the merge with gh pr merge <n> --auto --merge, never a direct merge: GitHub merges only once the independent review record mints review-record and every other required check passes. Otherwise request nothing and report "ready for owner merge" to your parent. Then output <promise>CONVERGED</promise>. Output it only when it is true.
